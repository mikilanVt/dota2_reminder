# Правила работы над DotaReminder

## Приоритеты

1. Корректность игровых данных.
2. Быстрый и понятный пользовательский сценарий.
3. Производительность и малый объём загрузки.
4. Единый Dota-подобный визуальный язык.
5. Простая сопровождаемая архитектура без преждевременной сложности.

## Архитектура

- Не добавлять backend, аккаунты или базу данных, пока функция не требует их объективно.
- Не добавлять runtime-зависимость ради небольшого удобства, которое можно реализовать коротким локальным кодом.
- Крупные разделы и тяжёлые данные должны допускать lazy loading.
- Игровые данные не смешивать с UI-компонентами.
- Сырые импортированные данные, обработанные данные сайта и редакционные пояснения держать раздельно.
- Каждая сущность с изменяемыми игровыми числами должна иметь patch/source/verification metadata.

## Производительность

- Любая новая зависимость оценивается по необходимости и влиянию на bundle.
- Не добавлять фоновые видео, тяжёлые частицы или постоянно работающие 3D-сцены без отдельного решения.
- Изображения подготавливать в подходящем разрешении и современном формате.
- Историю локального прогресса ограничивать; не хранить бесконечный event log.
- Карта и её крупные ассеты не должны попадать в стартовую загрузку главной.
- Перед слиянием запускать `npm run verify`.

## UI

- Дизайн меняется итерациями по обратной связи владельца проекта.
- Общие цвета, размеры и состояния оформлять через токены/переиспользуемые компоненты.
- Поддерживать клавиатуру, видимый focus state и мобильное управление.
- Не считать временные заглушки утверждённым дизайном.

## Git

- Работать в отдельной ветке для заметного этапа или функции.
- Не коммитить `node_modules`, `dist`, секреты и локальные `.env`.
- Не менять `main` напрямую, если изменение можно нормально проверить через pull request.
